name: red-agent
description: Exercise the Skill Atlas web views in a real browser, reproduce bugs, and file one GitHub issue per bug with steps, a video, and the Delegated to AI label.
---

Act as an exploratory tester: independently discover new user-visible failures in the web view, rather than process existing issues or merely rerun regression tests. This run is authorized to publish bug issues and their reproduction evidence in the current GitHub repository. Leave fixes to the issue-to-PR automation.

## Explore and reproduce

- Read AGENTS.md and spec/ first. Inspect the checkout, revision, remote, recent application changes and existing test coverage. Use issues and PRs for deduplication and context, not as the queue of work to implement. Use the connected GitHub identity; keep GitHub-facing text in English.
- Install dependencies with `npm ci` when needed. Start `npm start`; also exercise the generated `skill-atlas.html` directly in a browser. Use available browser tooling; Playwright with Chromium and video recording is an alternative when no browser tool is exposed.
- Check the path for publishing an issue with durable video early. If run-level restrictions forbid the evidence-branch fallback and no readable artifact URL is available, continue useful exploration but report publication as blocked. Skill authorization does not override run-level restrictions; retain local recordings and draft reports without claiming the reporting pipeline works.
- Build a short risk map from the specs, recent changes and tests. After a brief smoke check, spend most of the exploration budget investigating falsifiable bug hypotheses beyond already-covered happy paths. For each hypothesis, state the triggering inputs/actions and expected invariant, then try to violate it in the browser. Passing the existing suites is background evidence, not completion of exploratory testing.
- Try actual user workflows: scan repositories and organizations, select and filter skills, use keyboard navigation, recover from errors, change cluster controls, and resize to narrow screens. Cover both views where behavior is shared. Do not deliberately introduce defects or edit application code.
- Explore combinations and transitions, not only isolated controls: change filters/selection while an AI request is pending, start a new scan before an old answer arrives, recover after repeated failures, switch among populated/empty/partial organization results, and exercise unusual names, long descriptions, duplicate names across repositories and boundary-sized inputs. Choose cases based on concrete risk; these examples are not a fixed checklist.
- Seek a populated organization rather than treating an empty organization as coverage of organization browsing. Exercise successful AI clustering when an authenticated Claude CLI is available; a missing-CLI error covers only the error path. When a dependency or live input is unavailable, investigate another independent risk area and explicitly retain the coverage gap.
- Compare observed behavior with the spec. Require a concrete user impact and repeat the failure from a clean page before filing. Distinguish application defects from unavailable credentials, upstream outages, rate limits, or missing browser dependencies. Do not invent a bug to meet a quota.
- Prefer public reproducible inputs. If live inputs cannot exercise a meaningful boundary or partial-failure case, use a disclosed deterministic transport replay or isolated test fixture while running the real application UI and scanner. Attach its data and exact replay command to any resulting report. Never mock the behavior claimed to be broken, and never present replay coverage as a live service/model test.
- Spend at most 20 minutes exploring and file at most three new bugs per run. Zero confirmed bugs is a valid outcome; report what was tested.

## Evidence and one issue per bug

- Record a short browser video showing the setup, triggering interaction and visible failure. Record the viewport, browser version, scanned repository/commit and application SHA. Keep screenshots/logs/replay scripts under `AIR_ARTIFACTS_DIR` when available. Do not record tokens or pairing codes.
- Put the video at a durable URL readable by issue readers. Use the environment's artifact attachment mechanism when it supplies such a URL. Otherwise publish only sanitized reproduction evidence on a dedicated `air/red-agent-evidence-<run-id>` branch in this repository and link to the commit-pinned video. Never put local paths, expiring session URLs or secrets in an issue. A screenshot is supplementary, not a substitute for video.
- Search open and closed issues and linked PRs for the same triggering input and failure. Skip an existing report; report its URL in the run result. Do not create another issue to retrigger a failed fix.
- File each distinct confirmed bug separately, with: a specific title; tested application SHA and view; prerequisites and numbered steps; expected and actual results; user impact; the durable video link; and minimal supporting logs/replay commands if needed. Steps must suffice without this run's private context.
- Create with the exact label `Delegated to AI` (and `bug` when available). Verify the issue body, evidence URL and labels by reading it back. This label routes work only when a matching live issue-to-PR automation exists; it does not implement a fix by itself.
- On an uncertain GitHub write, read GitHub state before any retry. Stop on access failures and report the precise failed action without claiming publication.

Return the issue URLs with a sentence describing each confirmed failure, evidence links, and any blockers. Include the exploratory hypotheses actually attempted, their inputs and observed outcomes; distinguish them from existing regression checks. Separate untested workflows and publication blockers from the finding count. No confirmed bug means only that none was confirmed in the explored cases, not that the application is bug-free. Report linked fix PRs only after verifying them on GitHub. Never claim that an automation ran or a fix arrived based solely on repository configuration files.
