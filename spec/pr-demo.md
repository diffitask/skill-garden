# PR demonstration videos

- `.agents/skills/pr-demo/SKILL.md` records and publishes a short, annotated video of one to three user-visible PR changes. Manual input or an event selects a PR; absent manual input may use the sole open PR labeled `AI: review passed`, never an arbitrary choice among several.
- Compare real base/head browser interactions using identical input and framing for fixes. New features show a useful workflow. Captions and click indicators explain observed outcomes without modifying product behavior. Review frames and assert the demonstrated results. Nonvisual changes are reported as skipped rather than given a fabricated video.
- Visual style: full-screen Before and After chapter cards share a quiet solid background, a brief summary and a gentle transition, held for about two seconds. Revisions and fixture disclosure belong on chapter cards and in the report. During interaction the application fills the frame: no persistent top/bottom banners or subtitle bars. Use one short, lightweight annotation anchored near the relevant control/result, with a subtle leader line; keep target text visible and controls clickable. Remove notes between moments.
- `.agents/skills/pr-demo/scripts/annotations.mjs` supplies reusable Playwright chapter/callout overlays isolated from product styling. Notes choose an available side, stay within the viewport, follow scroll/resize and do not cover their target. Chapter cards dismiss before interaction. Missing or invisible callout targets fail visibly instead of recording a detached label. Browser integration tests verify placement at narrow/desktop widths, scrolling/resizing, chapter transitions, safe text rendering and interaction through the overlay. Include the helper with reproduction evidence when used.
- Keep recordings, preview, storyboard, sanitized replay and metadata as Air artifacts. Record base/head revisions, browser, viewport and tested views. Disclose deterministic transport/model fixtures in the video and report; they exercise real UI/scanner behavior but do not verify live services.
- Read trusted skill/helpers, inspect PR code before executing it in isolated detached checkouts, and keep credentials outside application/browser processes. Do not change application branches, merge PRs or manipulate readiness labels.
- A durable video URL readable by PR readers is required. Prefer a verified environment attachment; when authorized, a dedicated evidence-only branch with immutable commit-pinned links is the fallback. Local/expiring links, login pages and screenshots alone do not satisfy delivery. Report upload failures and preserve local evidence.
- `.air/scripts/publish-pr-demo.mjs check` takes `DEMO_REPOSITORY`, positive decimal `PR_NUMBER` and full lowercase `PR_HEAD_SHA`/`PR_BASE_SHA`. Require an open non-draft same-repository PR with exact revisions and the current `AI: review passed` label. Changed revisions, closed/draft/fork PRs and removed labels skip without writing.
- Inspect all pages of PR comments and skip an existing `pr-demo:v1:<head SHA>` comment. After slow reads, recheck the target before publication. This deduplicates sequential runs only: serialize manual runs; atomic coordination or enforced serialization is required before overlapping event/polling runs are enabled.
- Explicitly requested presentation revisions may set positive decimal `DEMO_REVISION` (safe integer >=2), adding `:r<revision>` before the marker's closing delimiter. Both preflight and publication then deduplicate that exact revision; preserve earlier comments. Without this variable, any presentation marker for the same head prevents an automatic duplicate, including when a revised presentation was the first publication. Do not auto-increment revisions. Invalid revisions fail before API access.
- `publish <comment-file>` additionally requires a nonempty report and credential-free HTTPS `DEMO_VIDEO_URL`; `DEMO_PREVIEW_URL` is optional. Reject malformed targets, invalid URLs and oversized comments before a write. Append one English comment with the video link, optional preview, base/head and marker; read back the exact body and PR membership. Preserve previous review/demo comments. New heads may get new demos. No automatic write retries: access, transport, malformed API responses and uncertain publication failures propagate for inspection.
- `.air/prompts/pr-demo.config.md` records the intended manual-first Air setup and actual validation evidence. Repository files do not activate an automation. Event trigger: `PR labeled` with `AI: review passed`; optional interval poll only after serialization is available. Evidence-branch publication requires a mode permitting evidence pushes, even though application code stays unchanged.
