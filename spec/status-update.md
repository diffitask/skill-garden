# Team status update

- The status-update skill reports merged PRs and currently closed completed issues for an explicit repository and timezone-qualified interval `[since, until)`. End defaults once to current UTC; invalid, reversed or future intervals and missing channel IDs fail before reading APIs.
- Paginate all closed repository issue candidates with GitHub CLI. Inspect PR merge timestamps separately; exclude unmerged PRs, not-planned issues and events outside the exact interval. Deduplicate by number, sort by completion time/number, and fail incomplete reads without posting.
- Produce one Slack message with repository, exact UTC interval, separate counts and linked PR/issue sections, including empty sections. Escape untrusted titles, suppress automatic mentions/previews and refuse oversized reports instead of truncating.
- Dry runs return a preview without Slack access. Delivery uses only environment `SLACK_BOT_TOKEN`, verifies an active private channel and bot membership, posts once, and succeeds only on Slack `ok: true` with matching channel and message timestamp. Never retry an uncertain write automatically or expose credentials in errors.
- Keep the Air prompt, required environment and activation status in `.air/prompts/status-update.config.md`. Repository files do not create a live automation. Recurring runs require a confirmed schedule/timezone, destination and initial start, serialized delivery and a durable successful end; failures/dry runs never advance that end.
- Integration coverage exercises the helper across pagination, interval boundaries, filtering, ordering/deduplication, empty/oversized output, dry runs, invalid configuration, private-channel validation and Slack/GitHub failures. Mocked transport tests do not establish real Slack delivery or Air activation.
